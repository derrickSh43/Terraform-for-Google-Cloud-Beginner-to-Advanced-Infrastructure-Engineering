The 24-week schedule is a suggested instructor-led pace. Self-paced students
can go faster.

## Done in lesson 06

- Multi-root lessons (`"roots"` in lesson.json): `envs/dev`, `envs/prod`, `bootstrap` are each planned; checks see `plan.others[...]`.
- Prepared deployed state (`"state"` in lesson.json, generated by `python -m coursekit.statefab`): dev is planned against the lesson 05 environment "as applied", so destroy/replace in a refactor is detected exactly as in a real PR.
- `coursekit.hcl.Source` for facts plan JSON omits (backend blocks, `lifecycle`, module `terraform` blocks).
- Native tests that target a child module directly (`run { module { source = ... } }`).

## Done in lesson 07

- `statefab` works on module trees (`python -m coursekit.statefab <tree> <out> envs/dev`) and writes
  realistic IDs/self_links (providers validate ID formats when one resource is passed to another),
  `*project` attributes and outputs.
- Self-test fails when a shipped state no longer matches the previous lesson's solution.
- Firewall evaluator: internet egress through Cloud NAT (region, network, subnet coverage),
  Private Google Access to the Google API VIPs, and internal sources (`internal_ip`) for peered ranges.
- `Plan.linked()` resolves references inside child modules.

## Done in lesson 08

- `coursekit/lb.py` traces forwarding rule -> proxy -> URL map -> backend service -> instance group -> VMs
  (references inside modules plus deployed IDs) and reports the first broken link.
- Google front-end and health-checker ranges are modelled as internal sources reaching the VMs.
- R8.8-style review: deployed-state plans where some deletes are *intended* (old firewall rules) but replacements are not.

## Done in lesson 09

- `Plan.linked()` follows references across module boundaries (`var.x` through the parent's
  module call, `module.c.out["key"]` through the child's output, keeping map keys).
- `lb.trace` resolves managed instance groups (regional and zonal) as backends, including
  `dynamic "backend"` blocks (absent from plan JSON), via the module's inputs.
- Instance templates work as firewall/egress endpoints, so fleets are checked like single VMs.

## Done in lesson 10

- `coursekit/iam.py`: effective grants from project-, bucket- and service-account-level IAM
  (member / binding / policy), service-account principals resolved by email or reference,
  custom roles expanded to permissions.
- `"state_from": "starter"` in lesson.json: the deployed state can include resources the starter
  adds (here, the audited `legacy-access.tf`), and self-test checks freshness against the starter.
- `statefab` writes realistic service-account `name`/`member`, custom-role and WIF-pool names.

## Done in lesson 11

- Checks read `lifecycle` blocks (`prevent_destroy`, `ignore_changes`) from HCL source, since plan JSON omits them.
- A fixture proves ForceNew detection: editing `metadata_startup_script` shows up as a replacement of the deployed VM.

## Done in lesson 12

- `iam.py` understands secret-level grants (`google_secret_manager_secret_iam_*`).
- `Source` reads `.tfvars` too; checks scan them for credentials.
- Output leak detection follows module outputs to the underlying resource attributes
  (`module.db.password` -> `random_password.app.result`).

## Done in lesson 13

- `iam.py` understands Artifact Registry repository and Cloud Run service grants, and flags
  public principals (`allUsers`, `allAuthenticatedUsers`).
- Route tracing from a URL map path rule through a backend service and serverless NEG to Cloud Run.
- Design note: the app VM was kept (its lesson 11 data disk has `prevent_destroy`), so the
  catalog API is a new serverless service rather than a migration.

## Done in lesson 14

- `iam.py` reads Pub/Sub topic- and subscription-level grants (service-agent permissions for dead-lettering).
- Self-test corrected a wrong claim: Terraform infers the `x` -> `x[0]` move when `count` is added, so the
  fixture for R14.8 uses a `for_each` change (not inferred) to prove the NEG-recreation check.

## Done in lesson 15

- Range-overlap checks cover primary and secondary subnet ranges, the PSA range and GKE control-plane ranges, across environments.
- "Additions only" can be stricter: R15.9 also rejects in-place updates to existing subnets.

## Done in lesson 16

- `coursekit/workflow.py`: stdlib-only YAML-subset reader and a workflow model (triggers, jobs, steps,
  permissions, conditions); `Source` now includes `.github/workflows/*.yml` and `*.tftest.hcl`.
- The runner executes student-written module tests (`modules/*/tests`) as their own stage.
- The HCL reader understands one-line blocks (`mock_provider "google" {}`).

## Done in lesson 17

- Checks combine plan values with HCL expressions for attributes that interpolate values known only after
  apply (e.g. an alert filter containing an uptime check ID).

## Done in lesson 18

- First multi-project root (`envs/hub`) with provider aliases; checks use each resource's `project`
  and `provider_config` to prove which configuration it used.
- Lesson tests can target a module directly: `tests/<level>/modules/<name>/*.tftest.hcl` run inside
  that module's folder (needed for modules with `configuration_aliases`).
- `statefab` writes realistic log-sink writer identities and notification channel names.

## Done in lesson 19

- `iam.py` reads Cloud KMS key-level grants.
- A fixture proves ForceNew detection for CMEK on an existing Cloud SQL instance; the lesson applies CMEK only
  where it's an in-place change.

## Done in lesson 20

- `coursekit/cloudsim.py`: offline `import` blocks. A lesson ships an inventory of hand-made objects
  (`"cloud": {"dev": "state/dev.cloud.json"}`); import IDs are resolved against it and written into the
  prepared state at the `to` address (Terraform skips imports whose address is already in state). Unknown
  IDs fail the plan like a real 404. `for_each` over literals/locals is supported. `plan.imported` holds the result.
- Drift drills: `"expected_drift": [addresses]` lets the freshness self-test accept deliberate in-place
  differences between the shipped state and the starter.
- `Plan.changed_attributes()`, `Plan.before()`, `Plan.check_results()` (check block status); `forget` actions
  from `removed` blocks are visible in `all_changes()`.
- `statefab` ignores `prevent_destroy` while fabricating (intermediate rounds replace resources).

## Done in lesson 21

- `coursekit/failure.py`: failure-domain analyser. Workloads (regional/zonal MIGs with their autoscaler,
  VMs, Cloud SQL, GKE, Memorystore) with zones and min/max capacity; `lose_zone`, `worst_case(at="min"|"max")`,
  `single_points_of_failure`. EVEN distribution: a zone loss costs `ceil(n / zones)`.
- `statefab` drops `import` blocks while fabricating (the fabricated state is the post-import state).
- Lesson finding: `prevent_destroy` doesn't protect a resource whose block is removed; the lesson uses `removed`.

## Done in lesson 22

- `failure.py` region loss: `data_stores(plan)` (buckets incl. dual/multi-regions and turbo replication, Cloud SQL
  with replicas and backup location, Artifact Registry) with the regions holding a copy and the RPO the
  architecture achieves; `lose_region(plan, region)`. Replicas are identified from configuration
  (`master_instance_name` expression), because prepared state holds placeholders.
- Pattern: prod-only features behind inputs whose defaults keep the old behaviour (dev plan = No changes).

## Done in lesson 23

- A fifth root, `envs/platform` (landing zone), planned with a fake organization ID and billing account.
  Folder/project numbers are unknown at plan time, so checks follow references with `plan.linked(...)`.
- Module-scoped lesson tests for the project factory (lab: label validation; challenge: ID length).

## Done in lesson 24 (capstone)

Design decisions: (1) the starter is the lesson 23 solution plus `docs/` stubs - the capstone proves,
automates and explains the platform instead of rebuilding it; (2) baselines re-run ~130 earlier lab
requirements, grouped by phase (R24.1-R24.4), leaving out one-off migrations and lesson-state guards;
(3) written deliverables are checked against `rubric.json` (structure) and against the plan (facts).

- `coursekit/baseline.py`: `require_all(plan, ["R21.5", ...])` loads earlier lessons' checks (cached) and
  reports every broken requirement with its original ID and message. The baselines found a real
  regression: lesson 22's DR replica was ZONAL, breaking R21.5 (no single point of failure in prod).
- `coursekit/docs.py`: stdlib markdown reader (headings, sections, word counts, pipe tables, fenced
  blocks, `Key: value` fields) and rubric checks for decision records.
- `Source.docs` (docs/**/*.md and top-level *.md) and `Source.paths` (every file, for evidence links).
- Checked docs: the architecture diagram must name every component type the plans build; the failure
  analysis tables must match `coursekit.failure` (zone loss in the lab, region loss vs objectives in the challenge).
- Self-test fixtures can delete folders (`"delete": ["modules/x/tests"]`).
